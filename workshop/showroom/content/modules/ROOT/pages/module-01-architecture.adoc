= Module 1: Explore the application architecture
:navtitle: 1. Architecture

== Know

An identity provider authenticates the user and issues tokens. Each application
and API still has to validate those tokens and make its own authorization
decision. A valid login does not automatically authorize every API operation.

The lab contains one frontend build configured at runtime for three patterns.
Orders is the protected API. Inventory and notifications demonstrate two
different service-to-service identities.

== Do

. Record your SPA, BFF, and proxy URLs from xref:details.adoc[]. Do not expect
  all three routes to be ready yet: the BFF and proxy need the realm you create
  in Module 2, and their clients and runtime settings from Modules 3 and 4.
. Locate the application architecture diagram in the existing project guide.
. Identify which process handles the browser callback in each pattern.
. Trace the Orders → Inventory and Orders → Notifications calls.
. In OpenShift Console, select your assigned project and inspect only your own
  Deployments and Services.

== Check

Be able to answer:

* Which pattern sends a bearer token directly from the browser to Orders?
* Which patterns keep the token on the server and give the browser a session
  cookie?
* Which downstream call should retain the user identity, and which uses a
  machine identity?

**Expected:** SPA PKCE sends a bearer token from browser memory; BFF and proxy
use session cookies. Orders exchanges the user token for Inventory and uses
client credentials for Notifications.

== If something is wrong

Before you finish Modules 2–4, the BFF or proxy can be unavailable because its
realm, client, or runtime configuration is not ready. The proxy can also show
Keycloak's **Client not found** message before the `proxy` client exists in your
realm. These are expected setup states; they do not mean that you should
change a shared route.

After Module 4, check that your own realm contains the matching client, the
application configuration uses your exact issuer and client ID, and the
application deployment is ready in your assigned namespace. Then retry the
route. If those checks pass and the route still fails, ask the facilitator to
check your reservation. Do not change routes or deployments in the shared
`apps` namespace.
