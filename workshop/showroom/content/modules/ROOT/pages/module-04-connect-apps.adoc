= Module 4: Connect the applications
:navtitle: 4. Connect apps

== Know

These applications were built before the lab. You will connect them by changing
runtime configuration in your own namespace. The SPA reads `/config.json`;
server-side components read environment values from ConfigMaps and Secrets.
No source edit or rebuild is needed for this activity.

== Do

. In OpenShift Console, select your assigned namespace and confirm the SPA,
  BFF, and proxy Routes match your session handoff.
. Update only the listed fields in each ConfigMap. Keep service URLs and other
  reservation-generated values unchanged. Each row names the workload that
  consumes that ConfigMap.

[cols="1,2,3,1",options="header"]
|===
|ConfigMap |Fields to set |Value |Consuming workload
|`frontend-runtime-config` |In `config.json`, set `issuer` and `spaClientId` |Your exact realm issuer; `spa` |frontend
|`bff-config` |`OIDC_ISSUER` |Your exact realm issuer; the Keycloak client ID remains `bff` |bff
|`proxy-config` |`issuer`, `redirect-url` |Your exact realm issuer; `{proxy_url}/oauth2/callback` |proxy
|`orders-api-config` |`ISSUER`, `WORKSHOP_ISSUER`, `SPA_ORIGIN` |Your exact realm issuer for both issuer fields; exact SPA origin |orders-api
|`inventory-api-config` |`ISSUER` |Your exact realm issuer |inventory-api
|`notifications-api-config` |`ISSUER` |Your exact realm issuer |notifications-api
|===

. Leave `INVENTORY_API_URL`, `NOTIFICATIONS_API_URL`, and
  `proxy-runtime-config` as provided; they must continue to use the
  namespace-local services and runtime settings.
. In the matching Secrets, enter each corresponding client secret created in
  Module 3: the `bff` client secret in Secret `bff-client`, key
  `BFF_CLIENT_SECRET`; the `proxy` client secret in Secret `proxy-secrets`, key
  `client-secret`; and the `orders-api` client secret in Secret
  `orders-api-client`, key `client-secret`. Keep `cookie-secret` and
  `redis-password` unchanged. Edit Secrets through the private OpenShift
  Console session; keep values out of terminal arguments, screenshots, and
  shared logs.
. Restart only the workloads whose ConfigMap or Secret you changed. Wait for
  each restarted workload to report Ready before retrying its route.

== Check

Reload `/config.json` from your SPA route. It should show your exact realm
issuer and `spa` client ID, with no secrets. Then retry sign-in as the reader
through each configured route: SPA, BFF, and proxy. Each must return to its
own approved callback.

**Expected:** login succeeds against your realm and each app stays within your
namespace. The client secret does not appear in browser configuration.

== If something is wrong

Check issuer character-for-character, callback scheme/path, client ID, and
Secret key names: `BFF_CLIENT_SECRET` in `bff-client`, `client-secret` in
`proxy-secrets` and `orders-api-client`. A stale pod may need a rollout restart
after a ConfigMap or Secret change. A BFF or proxy route can return 503
before the realm and clients exist; after this module, verify the issuer and
pod readiness if it persists. If the pod reports `ImagePullBackOff`, pause:
this is a reservation image-pull setup issue, not a learner task.
