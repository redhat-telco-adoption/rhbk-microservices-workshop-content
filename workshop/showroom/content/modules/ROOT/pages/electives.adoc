= Electives
:navtitle: Electives

The electives go deeper into questions that come up when Keycloak becomes the
central identity platform: groups, signing keys, token introspection,
fine-grained authorization, and tokens from other issuers. They are
self-paced. Your environment stays available after the session, so you can
finish them later.

Each elective starts from a realm completed through Module 6 and is
independent of the others. Each one ends by leaving your realm in a state
where Modules 5 and 6 still work.

== The terminal

Open the **Terminal** tab at the top of this guide's right-hand pane. It is a
shell in your own Showroom pod with `curl` and `jq`. Electives B, C, D, and E
use it.

Run this setup block each time you open a new terminal. It asks for the
`orders-api` client secret, which you find in Keycloak under **Clients →
orders-api → Credentials**. `read -s` keeps the secret off the screen and out
of the shell history.

[source,bash,subs="attributes+"]
----
export ISSUER='{issuer}'
export ORDERS_API='{orders_api_url}'
read -rsp 'orders-api client secret: ' ORDERS_SECRET; echo
# A fresh access token for the orders-api service account.
sa_token() { curl -s -u "orders-api:$ORDERS_SECRET" -d grant_type=client_credentials "$ISSUER/protocol/openid-connect/token" | jq -r .access_token; }
# Store a user's access token copied from the browser, with or without "Bearer ".
paste_token() { read -rsp 'Access token: ' TOKEN; echo; TOKEN=${TOKEN#Bearer }; }
# Show one part of a JWT: 1 is the header, 2 is the payload.
jwt_part() { local p; p=$(cut -d. -f"$2" <<<"$1" | tr '_-' '/+'); while (( ${#p} % 4 )); do p+='='; done; base64 -d <<<"$p" | jq .; }
----

Check it: `jwt_part "$(sa_token)" 2 | jq '{iss, azp}'` prints your issuer and
`orders-api`. If it prints `null` values, the secret is wrong; run the
`read` line again.

image::el-terminal-setup.png[Terminal after the setup block, showing the issuer and azp orders-api]

To copy a user's token, use the browser's **Network** tab as in Module 5:
select an `orders` request and copy the `Authorization` header value. Then run
`paste_token` and paste it. Access tokens expire after five minutes; copy a
fresh one when a step says the token expired.

Treat every token and secret in this terminal as a credential. Do not paste
them into tickets, chat, or files.
