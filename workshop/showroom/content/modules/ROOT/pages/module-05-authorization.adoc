= Module 5: Verify authorization decisions
:navtitle: 5. Allow and deny

== Know

Authentication identifies the caller. Authorization evaluates role, audience,
issuer, and sometimes client identity for each protected API operation. A
client-side button is not an authorization control.

== Do

Each app page has the same two buttons: **View orders** sends `GET /orders` and
**Create a sample order** sends `POST /orders`. The result and response code
appear in the message below the buttons.

. Open your link:{spa_url}[SPA,window=_blank] and click **Sign in**. A sign-in
  popup opens; sign in as `reader` with the lab password you chose in Module 2.
. Click **View orders**, then **Create a sample order**, and record both
  response codes.
+
image::m05-spa-reader-denied.png[SPA showing the reader's write denied with 403]

. Click **Sign out**, then sign in as `manager` and repeat both buttons.
+
image::m05-spa-manager-created.png[SPA showing the manager's order created with 201]

. Repeat the reader and manager checks through your
  link:{bff_url}[BFF,window=_blank] and link:{proxy_url}[proxy,window=_blank].
  The proxy has no **Sign in** button: opening it sends you straight to the
  Keycloak sign-in page. Sign out between users; signing out also ends your
  Keycloak session, so the next sign-in asks for a username again. If the
  proxy page still shows **Sign out** after you click it, reload the page.
+
The three apps share one Keycloak sign-in in your browser. If you are still
signed in to one app, another app signs you in as that same user without
asking. Sign out of the app you used last before you switch users.

== Check

Record the results:

[cols="1,1,2",options="header"]
|===
|Identity |Operation |Expected
|reader with `user` |GET `/orders` |Success
|reader with `user` |POST `/orders` |Denied
|manager with `manager` and composite `user` |GET `/orders` |Success
|manager with `manager` and composite `user` |POST `/orders` |Success (201)
|===

**Expected:** the API enforces the decision. A reader cannot gain write access
by editing the UI or changing a request in the browser.

== If something is wrong

For an unexpected denial, check the token issuer, audience, role claim, and
expiration before changing policy. For an unexpected success, stop and notify
the facilitator; do not broaden the role or audience to make the test pass.
