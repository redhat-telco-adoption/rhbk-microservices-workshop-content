= Module 7: Observability and production tradeoffs
:navtitle: 7. Observe and review

== Know

Useful observability answers which operation failed, which service handled it,
and which sanitized identity attributes were involved. Logs and traces should
not expose passwords, client secrets, session cookies, or bearer tokens.

== Do

. Make one successful read and one denied write in your application copy.
. Open link:{openshift_console_url}/observe/traces?namespace=tracing&name=workshop&tenant={attendee_id}&start=15m&limit=100&q=%7B+resource.service.name+%3D+%22orders-api%22+%7D[your Orders traces,window=_blank] again and find the
  denied `POST /orders` trace. It stops at
  Orders with status 403 and never reaches Inventory or Notifications.
. In **Observe → Logs**, search for `deny` and click **Run Query**; if the old
  results stay, click the refresh button. The Orders line shows
  `decision` `deny`, status 403, and `reason` `missing_role`, with no token or
  secret in the log. A denied write through the BFF also has a BFF line with
  `roles: []`: the BFF logs its session's ID token, which carries no roles,
  while Orders checks the access token.
+
image::m07-deny-log.png[Orders log line for the reader's denied write]

. Write one sentence for each pattern describing where the browser session
  lives, how logout works, and the main operational dependency.
. Write down how you would handle client lifetime, role ownership, redirect URI
  policy, token lifetime, secret rotation, and audit-event retention in
  production. If you work with a partner, compare notes.

== Check

Share a short production recommendation that names the pattern, threat or
operational constraint it addresses, and a control you would add before
production. Ensure your evidence contains no credentials or raw tokens.

**Expected:** your recommendation accounts for browser token exposure, BFF or
proxy availability, CSRF, exact redirects, audience restrictions, least
privilege, audit data, and recovery.

== Optional legacy API activity

The project’s Legacy API depends on AWS, DNS, subnet, EC2, and publicly trusted
TLS prerequisites. Use it only when your facilitator explicitly confirms it is
available. Confirm the audience is `legacy-api`, test the prepared endpoint,
and compare its identity evidence with the cluster APIs. Otherwise mark it
skipped.

== If something is wrong

Logs and traces can take up to a minute to appear; refresh the search. If
**Observe → Logs** or **Observe → Traces** is missing, ask the facilitator to
check the shared logging and tracing stack. Never request cluster-wide logging
access for this exercise.
